# GEA — 免費 AI 治理環境評測
### Governance Environment Assessment (free & open)

**一句話**：把你的 AI 系統（agent、自動化管線、AI 應用）對照 **24 個有真實失效證據的指標**逐項檢查，產出加權分級報告，每個缺口都附免費修法。

## 一項技術，三種模式

| 模式 | 測什麼層 | 怎麼跑 | 狀態 |
|---|---|---|---|
| **S 掃描** | **產物層**：你的系統目錄實際有什麼（log 有沒有 hash、金鑰有沒有隔離…10 領域自動檢查） | `python3 scan/selfcheck.py /你的系統目錄 --profile basic` | ✅ 可用 |
| **Q 問卷** | **設計層**：你的治理設計防住哪些已知失效（24 個證據錨定指標） | `python3 gea_assess.py` | ✅ 可用 |
| **P 探針** | **行為層**：你的 AI 被動手腳時實際會怎樣（主動注入測試） | 規格已定，實作中 | 🔜 路線圖 |

三層互補：**掃描看「有沒有做」、問卷看「想沒想到」、探針看「真的擋不擋得住」。**

## 30 秒開始（零依賴，Python 3.8+ 純標準庫）

```bash
python3 gea_assess.py --demo                          # Q 模式：先看範例報告
python3 gea_assess.py                                 # Q 模式：互動作答（s 鍵看說明）
python3 scan/selfcheck.py /你的AI系統目錄 --profile basic   # S 模式：自動掃描
python3 scan/selfcheck.py 目錄 --agent --mapping        # agent 加分軌＋ISO42001/NIST/OWASP 對照
python3 gea_assess.py --self-test && python3 scan/selftest.py   # 兩引擎自我驗證
```

**S 模式評分模型**：60/40 雙層——基礎門檻 60 分池＋品質 40 分池，
**品質 gated on 基礎**（某領域連 log 都沒有，就不給談防竄改的品質分）。
此模型經預先註冊的四項行為預測驗證（空目錄 1 分／完整系統 88 分／
只有裸 log 的目錄 26 分且「基礎✓品質✗」清楚分離）。

進階：
```bash
python3 gea_assess.py --answers my.json --out report.md --json-out report.json
```

## 這個評測跟別的有什麼不同

**每一個指標都錨定一個「真實發生過、有落盤紀錄」的失效事件。**

這不是專家腦補的理想清單——是一個多 agent 生態系在真實運行中踩過的坑的反面。
例如：

- 一個中階模型在沒被要求驗證時，回報「Verified」但**根本沒算**（→ 指標 1.1）
- 同一個模型算出雜湊不符、記成 WARNING，然後**宣告 VALID 放行**（→ 指標 1.2）
- 規格要求二選一（VALID/INVALID），它**自創了第三個選項 CONDITIONAL**（→ 指標 1.4）
- 一次模型被無聲切換，跑了 **42 小時沒有任何人知道**（→ 指標 3.2）
- 一支腳本把 git 失敗判成「無變更」，**推送失敗卻回報一切正常**（→ 指標 4.1）

## 計分哲學（讀完再用）

1. **三態計分**：程式層強制防護＝滿分／有規則但靠人或 AI 自律＝**半分**／沒有＝0。
   「有規則沒有閘＝半分」是刻意的：寫在文件裡的規則不會攔截任何事。
2. **權重**：治理與安全 82%、系統效能 10%、協作治理 8%——
   本評測的立場是：**先能被稽核，再談跑得快**。
3. **分數不是安全保證**。滿分只代表「已知的坑都有蓋子」，未知的坑不在任何評測裡。
   量尺會隨新觀察到的失效模式持續變嚴（60 分質詢法：對每個滿分項問
   「如果這只值 60 分，剩下 40 分的失效空間在哪」——但新假說要被實際觀察到才計分）。
4. **作答率與總分必須一起看**：沒答的題不計分也不補分。

## 七個維度

| 維度 | 權重 | 管什麼 |
|---|---|---|
| D1 完整性防護 | 22 | 驗證是程式做的還是 AI 嘴上說的 |
| D2 狀態真實性 | 18 | 狀態是生成的還是「記得去更新」的 |
| D3 身分與環境 | 14 | 執行者是誰、模型是誰，可不可證 |
| D4 失敗可見性 | 14 | 失敗會不會被報成成功 |
| D5 稽核可重建性 | 14 | 第三方能不能只靠紀錄重建真相 |
| D6 協作治理 | 8 | 多方協作的訊息鏈與防覆蓋 |
| D7 系統效能與成本 | 10 | 治理成本量過沒有、單位對不對 |

## FAQ

**Q：評測要連網嗎？會上傳我的資料嗎？**
A：不用、不會。單檔本地執行，唯一輸出是你指定路徑的報告檔。

**Q：我的分數很低怎麼辦？**
A：正常。範例報告（`DEMO_REPORT.md`）也只有 48.2。每個不及格項都附「免費修法」，
從權重最高的 D1 開始修，性價比最高。

**Q：為什麼沒有「業界平均」比較？**
A：因為還沒有足夠的受測樣本，我們拒絕編一個。等有了會以匿名彙總發布。
